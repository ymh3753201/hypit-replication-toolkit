# 视频复刻优化使用说明

版本：0.1.0，2026-09-30。入口：项目根目录 `./bin/replicate`；也可用 `./bin/hypit replicate`。

本版本已实现任务核对、收费提交保护、结果复用、分层剪辑和逐项审阅。程序能减少漏项与误操作；人物、商品、音色和口型是否达标，仍须看真实出片。此轮开发只用合成素材、模拟接口和本机服务，未创建真实收费模型任务。

## 1. 每次先建立新任务

在 `productions/<新任务名>/` 保存：

- `Brief.md`：用户原话、替换项、严格保留项、声音目标、预算和次数授权。
- `analysis.md`：观察原片的镜头、动作、台词，以及全屏、小窗、商品和转场出现位置。写清审阅人、各参考的用途和方案选择理由。
- `Script.txt`：权威台词，只维护这一份。不要在别处另写一套台词。
- `task.json`：执行记录。复制 `packages/replication-workflow/examples/task.example.json` 后按真实要求填写。模板授权为零且未确认分析，不能直接收费运行。
- 原视频、图片、音色：放在任务目录；文件名对应素材记录。Hypit 素材必须位于项目内，外部本地素材先复制进来，保留原件。

AI 先观察素材，再填写记录。`regionsComplete` 和 `requirementsReviewed` 只表示已经完成语义复核，不能由程序替 AI 或用户“理解完视频”。不能随意勾选。

### 视频链接与长视频

```sh
./bin/replicate fetch '实际分享链接或媒体地址' productions/new-task/source.mp4
./bin/replicate split productions/new-task/source.mp4 productions/new-task/segments
```

`fetch` 沿用上游媒体下载，随后验证是真视频。站点登录、限流或下载失败会停止，不把分享网页传给模型。

`split` 完整覆盖原片，保存每段起止点、文件指纹和原片信息，不裁掉尾段。为了避免不足 4 秒的尾段，它按整个时长均分，每段最多 15 秒。**这是技术分段；AI 仍须结合镜头和台词调整语义边界，并登记总任务数。** 原片不足 4 秒时停止，先明确处理方式；不足 2 秒的参考片段也不能直接交给 H3。兼容转码保留音轨，不默认去声。

H3 输出为整数秒；例如 10.4 秒参考可能规划 11 秒输出，时长差异须在制作要求中明确，不能承诺逐帧复原。

## 2. task.json 如何填写

| 字段 | 意义 |
|---|---|
| `id`、`revision` | 稳定任务编号和修订次数。编号用英文、数字、短横线或下划线 |
| `assets` | 每份素材的编号、文件、对象、用途和说明。`identity` 为身份，`product` 为商品，`motion` 为原片动作，`voice` 为音色 |
| `requirements` | 人物、商品、动作、镜头、场景、风格、声音、台词的保留/替换/改变要求；`basis` 记录用户依据 |
| `referenceIds` | 真正连接到模型的素材，不能仅在提示词中提到文件名 |
| `requirementIds` | 当前片段处理哪些要求。整片每项要求必须有安排 |
| `occurrences` | 人物/商品的出现区域和片段内时间。小窗单独登记，来源为本片段 `generated` 动态结果 |
| `authorization` | 服务、模型、次数、金额、授权人、依据、日期和适用任务。可加 `expiresAt`，用含时区的日期 |
| `pricing` | 已核对的价格、分辨率、来源、查询日期；不能把估算说成账单 |

同一主体的不同属性可分别处理：保留衣服、替换脸时使用不同 `attribute`。同一属性同时要求保留与替换会停止。多人物用不同 `subject`、图片和出现区域，不能把一个人的参考自动当成另一个人。

程序按图片、视频、音频分组连接，保留各组内部的编号顺序；这也会出现在提示词和付费前最终核对中。实际文件字节、顺序、提示词、时长、模型和代码版本都绑定到计划。

### 选择制作方式

- `direct_edit`：保留指定动作、镜头或人与商品交互；必须连接原片视频，原片用途包含 `motion`。
- `performance`：允许重新表演，生成一段可用于全屏和小窗的动态素材。不能用它悄悄取消 `exact: true` 的动作/镜头要求。
- `reuse`：复用已经通过的动态表演，需明确原 `plan.json`、原片段编号、适用性复核人及依据。它不会新建 H3 请求，但当前任务仍须重新验收，不继承旧任务的通过结论。

```json
{"strategy":"reuse","reuse":{"manifest":"../old-task/.replication/准确计划指纹/plan.json","segmentId":"s1","applicabilityReviewedBy":"实际核对人","basis":"为何适用于当前要求"}}
```

当前版本按整片设置声音目标和一套权威最终录音。多个说话人或逐段换声时，先核对实际模型、接口及本工具的表达能力；不能仅因多人出现就自动拆分付费请求，也不能把一个全局音色字段冒充复杂声音编排。模型支持而当前流程不能表达时，应说明工具适配不足，先制定免费兼容方案，不默认新增视频或配音调用。通用任务使用 [复刻视频通用提示词](../复刻视频通用提示词.md)。

### 声音目标

| `audio.mode` | 处理方式 |
|---|---|
| `generated` | 用文字描述新声音，同一次 H3 请求生成画面和声音；普通声音不能宣称稳定指定本人音色 |
| `voice_reference` | `assetId` 指向真实音色文件，实际连接 H3；只参考音色，权威台词由脚本决定 |
| `preserve` | 最终保留原视频/录音声音；生成画面时不要求第二份口播 |
| `recording` | 最终直接使用指定录音，不能把它说成模型换声成功 |
| `silent` | 最终无声，适合明确要求静音的素材；与台词/声音要求冲突时停止 |

`preserve/recording` 的声音源须覆盖整片。新声音、台词、口型需逐项验收，不默认新增 TTS、第二次配音或换收费服务。

## 3. 收费前两道核对

```sh
./bin/replicate prepare productions/new-task/task.json
./bin/replicate check productions/new-task/task.json
./bin/replicate task-status productions/new-task/task.json
```

以上命令不创建收费任务。`prepare` 保存素材指纹、完整提示词、实际连接、保守费用和专用 Runtime（执行配置）。`check` 真正调用上游 `check/plan`，确认每个生成片段只指向官方 H3，没有额外配音或增强请求。

缺失图片/音色/台词、遗漏实际连接、冲突要求、素材限额、授权不足会停止。参考视频和音频分别最多 3 份且各总计不超过 15 秒；图片最多 9 份，三类总计不超过 12。首尾帧不能混入多参考或音色模式。语速偏高只提示复核，不擅自删词。

费用按整片累计，参考视频也计价；输入视频秒数暂按向上取整估算。示例价格是 2026-09-30 核对的官方价格，正式执行前重新核对；改分辨率也必须更新对应价格。价格来源：[官方价格表](https://platform.minimax.cn/docs/guides/pricing-paygo)。实际费用以官方账单为准。

新增收费请求前，素材、脚本、Run、Runtime 和实现代码都须与已审核计划一致。发生变化须重新 `prepare/check`；已提交的计划需要再次生成时必须增加 `revision`，核对是否确有新生成授权。同一授权编号的金额、次数、依据和范围不能覆盖修改；必要时使用真实的新授权编号。

工具升级后，历史要求、素材、输出和证据未变的合格表演仍可复用，已有官方任务仍可恢复查询、登记和导出。程序保留当时的实现版本记录，兼容旧版计划，不为复用自动重新生成。复用到新任务必须确认适用性，并重新验收新任务的各项要求。修改历史脚本、素材、证据或剪辑来源，仍会使相关验收失效。

### 已有授权下提交

```sh
./bin/replicate build productions/new-task/task.json --submit
# 可只执行一个已规划片段：
./bin/replicate build productions/new-task/task.json s1 --submit
```

`--submit` 表示这是收费动作，不替代用户授权。沿用用户已经给出的预算与次数，不要求逐步骤重复确认。不得伪造 `approvedBy/basis`。

新 Runtime 在官方 Provider 真正 POST 前再次核对请求和素材字节。执行意图、共享账本和进程锁限制重复提交；同一个授权覆盖多个任务时，必须列出相同 `taskIds`，占用次数和费用共享累计。程序不会在质量失败后自动追加请求，也不会自动切换模型。

## 4. 异常恢复

- 已有官方任务号：再次执行同一计划仅恢复查询/下载。查询或下载的短暂错误不会新建视频任务。授权期限到期后仍可查询已有回执。
- `submission_unknown`：远端可能已受理但回执不可靠。次数和金额保持占用；先查官方任务和账单，不能清账本后再投。
- 已确认原官方任务号，可写人工核对回执，再关联：

```json
{"segmentId":"s1","officialTaskId":"真实原任务号","verifiedBy":"核对人","basis":"官方任务记录的核对依据"}
```

```sh
./bin/replicate reconcile productions/new-task/task.json productions/new-task/receipt.private.json
```

- 崩溃遗留锁：`./bin/replicate recover-lock` 仅允许本机持锁进程已经结束；未知提交不会释放额度，账本保持原样。
- 缺少或损坏 `owner.json`：先停止所有旧版复刻进程，再执行 `./bin/replicate recover-lock --legacy-workers-stopped`。该参数是“已停止旧进程”的明确确认，不会替你结束进程；未确认时停止恢复。来自其他主机的锁仍会被拒绝。
- 新版用项目 Node 24 自带的 SQLite 提供系统锁，串行保护账本操作和整个恢复过程；进程退出时系统释放保护。不要删除 `ledger.guard.sqlite`、账本或锁目录来强行恢复。升级时先停止旧版工作进程；同时运行旧版和新版不能获得这项完整保护。Node 可能显示 SQLite 实验性功能提示，这是运行时提示，版本升级后应重跑免费测试。
- Build 尚未完成或失败：停止后续片段，保留编号。CLI 意外断开时先用上游 `inspect` 查询原 Build；确认原 Build 完成后可用同一计划恢复登记。不要换任务名重新投。

保护是本机的误操作防护。主动更换旧通用 Runtime、另调用全局 CLI、删除账本或改代码能够绕过它，因此 AI 必须遵守本项目入口。程序不宣称远端接口有幂等保证，也不承诺所有网络故障下绝对只扣一次。

## 5. 模型原件与逐项验收

先导出本次准确 Build 的 `replacement.video`：

```sh
./bin/replicate export-model productions/new-task/task.json s1 实际模型Build编号
./bin/replicate review-template productions/new-task/task.json model s1 > productions/new-task/review-checks-model.json
```

每个输出必须对应官方任务的下载指纹和当前计划的完成 Build；原片或其他任务文件不能顶替。

模板默认全部 `unverified`（未验证）。真实观察后逐项填写，不允许整页自动填通过：

```json
{
  "kind":"model","segmentId":"s1","observedHash":"模板显示的准确输出指纹",
  "checks":[{
    "key":"requirement:actor","verdict":"pass","reviewer":"实际审阅人",
    "method":"visual","coverage":{"start":0,"end":5},
    "note":"实际看完的身份一致性结论，不能只是接口返回成功",
    "evidence":[{"file":"实际证据文件的绝对路径","sha256":"证据文件指纹"}]
  }]
}
```

`visual` 表示看画面；声音/台词/最终混音必须为 `listening`（听完整声音）；口型为 `audiovisual`（同时看和听）。画面覆盖完整要求范围，不能用开头一帧替代全片。可保留原 MP4 并附截图或听音记录；证据文件需真实存在，指纹可用 `shasum -a 256 <文件>` 查看。程序只能核对记录和证据版本，不能证明审阅人确实看过或替人判断脸、商品和音色。

**通过需要完整观察；失败允许登记已发现的局部问题。** 例如在 1.2–1.5 秒看到小窗仍是旧人物，就按这段真实范围填 `fail`，无需谎称看完整片。范围必须有效、位于当前文件内，并与该小窗的出现时间重叠。声音、台词和口型同样允许局部失败证据；先前的通过结论会被这次真实失败覆盖，整片状态变为 `quality_failed`。局部观察不能登记为整项通过。

```sh
./bin/replicate review productions/new-task/task.json productions/new-task/review-checks-model.json
```

任一必需项失败为 `quality_failed`；缺少或未验证为 `awaiting_review`。只有所有必需项通过才为 `accepted`。没有音轨是技术事实；有音轨不表示目标音色/台词正确。原模型有声而预览静音，先查剪辑声轨，不能宣称模型无声。

## 6. 同一表演复用、分层剪辑与 Studio

模型片段通过后复制并填写 `examples/layout.example.json`。小窗和卡片位置用画布百分比，字幕使用精确本地字体文件；新增字体放项目内，并登记 `fontFile`。`captions` 按起止秒和文字填写，精确商品文字也可本地重建。布局必须覆盖已登记的小窗，否则停止。

```sh
./bin/replicate compose productions/new-task/task.json productions/new-task/layout.json
./bin/replicate render productions/new-task/task.json
./bin/replicate export-final productions/new-task/task.json 实际剪辑Build编号
./bin/replicate studio productions/new-task/task.json 5185
```

生成的 `review.svml/review.svs` 有独立画面、卡片、字幕和音频轨。全屏与小窗连接同一动态结果，按同一时间位置裁取；只有一个最终声音来源，不叠加小窗声音。这些原生层可在上游 Studio/源码中编辑，本轮没有重写 Studio。

审阅 Runtime 只含本地媒体与渲染服务，没有 H3、收费配音或提示词增强能力。`render/studio` 再次核对计划。修改字幕或布局后执行 `render`，会绑定新的本地剪辑版本；改模型文件/录音/字体或 Runtime 则停止，需重新核对 `compose`。Studio 打开成功和实际人工视听验收分别报告。

`render` 完成才绑定成片 Build；`export-final` 拒绝无关 Build。再次导出清空旧验收。修改成片、证据或剪辑输入后，旧结论失效。最终逐项验收还包括所有出现区域（含小窗）、商品、声音、台词、口型和混音：

```sh
./bin/replicate review-template productions/new-task/task.json final > productions/new-task/review-checks-final.json
# 完成真实逐项审阅后：
./bin/replicate review productions/new-task/task.json productions/new-task/review-checks-final.json
./bin/replicate task-status productions/new-task/task.json
```

`accepted` 需要模型源片段和最终各项均有效。局部人物成功、模型状态成功、音轨存在或工作台已打开，均不能独自作为整片交付通过。

### 记录实际费用

账单确认后记录 `officialTaskId`、`actualCny`、`verifiedBy`、`basis`、`evidence:{file,sha256}`：

```sh
./bin/replicate record-cost productions/new-task/task.json productions/new-task/bill.private.json
```

未关联账单的金额显示为未知；不会把预估费用说成实际扣费。每笔授权占用按“原预留与已核实实付中的较大值”计算，实付向上换算到分。更便宜不自动释放额度；更贵会增加占用。授权 10 元，首笔预留 5 元、已核实实付 8 元时，第二笔预估 5 元会被阻止；原任务查询和下载仍可恢复。

`task-status` 的 `reservedCny` 是原预留合计，`occupiedCny` 是实际用于预算保护的占用，`billedCny` 是全部账单均已关联时的实付合计，否则为 `null`。共享授权覆盖的各任务共同累计。程序不能预知尚未到账的官方费用，正式价格仍须在提交前核对。

## 7. 验证与升级

```sh
./bin/test-replication
```

包含业务检查、并发/异常、真实 Hypit plan、模拟官方 Provider、真实本机 Worker、合成素材本地渲染和原有适配器回归。测试里的“通过”仅用于验证状态规则，人物和声音用的是合成测试数据，不能作为真实业务验收。

本轮已验证：两种制作方案合法输入、指定音色连接、商品连接、多主体、首帧模式、静音/保留原声、分段完整性、重复/未知提交保护、原任务恢复、合格源复用、分层渲染与版本失效。

审查修复回归另覆盖：仅换商品/场景/声音、换服装保留脸、整个人物替换和多人物仅换一个；新旧计划在模板/工作流/Provider 升级后的历史复用及新收费拦截；局部失败登记；共享授权的已核实费用；无 owner、损坏 owner、活锁、死锁、恢复竞争及崩溃后的系统锁释放。服装替换使用 `person` 的 `attribute:"clothes"`，其图片用途为 `purposes:["clothes"]`，不要把服装参考声明成换脸依据。

仍需真实出片：人脸/商品准确性、指定音色、逐字台词、口型、带货交互、严格动作镜头、换场景/风格、长视频各段一致性；尚未测得首次合格率或合格成片成本。不默认安排收费测试矩阵。

新增代码在外层三个独立包中；内层只改现有本地官方 Provider 的配置传递、提交保护和素材模式校验，没有修改 Hypit 核心或上游 Skill。源码与外层包须配套使用。每份计划记录两仓提交、上游基线和实现文件指纹。

同步上游先遵循 `docs/GIT工作流.md`，在临时同步分支合并后重跑上述无扣费检查。若 plan JSON、原生词汇或 Provider 上下文变化，修薄适配层；不批量覆盖上游。回退代码不删除 `.hypit/replication-ledger` 或任务 `.replication`，也不把已提交任务当成全新调用。

业务执行记录默认忽略，不提交密钥、签名 URL、素材、生成结果或费用私密信息。脱敏模板、源码和测试可以进 Git。
